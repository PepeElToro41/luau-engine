# standalone and editor

`LuauEngine::engine`: INTERFACE target linking all three.
`standalone/` and `editor/` link this.
Each is a `main.cpp` that adds plugins to an `Engine` (`engine/runtime/CLAUDE.md`), calls `init()`, `run()` and `shutdown()`: `WindowPlugin`, `CorePlugin`, `RenderPlugin`, `PlayPlugin`, `ProjectPlugin`, `ScenePlugin` and `DemoPlugin` for both, the editor's own five in between.
The standalone's `PlayPlugin` runs the game in place from startup (`--isolate` runs it in a clone of the loaded world instead, the editor's Play path without the editor, which is how that path is checked), the editor's clones on Play.
Standalone renders the engine straight into `GpuFrame::backbuffer` (the window plugin's runner), opens a project directory (`--project <dir>`, the testing project by default, baked in as `STANDALONE_DEFAULT_PROJECT_DIR`), registers every asset file under it, loads `--scene <path>` (relative to the project, `scenes/demo.scene` by default) and draws from the scene camera tagged `RenderCamera` (else the first camera under `scene_root`, which `ScenePlugin` tags);
its asset provider accepts uncooked files unless `--cooked` is given, since a development project's imports are not cooked.
The editor's plugins are in `editor/src/plugins/`: `EditorViewportPlugin` renders the scene into per-slot viewport textures (sRGB with a UNORM `sampled_format`, so ImGui copies the encoded bytes through to the UNORM swapchain, `SCENE_FORMAT` / `UI_FORMAT`) by pointing the `FrameContext` at this slot's texture in `pre_render` and, in `post_render`, barriering it to SAMPLED and pointing the context back at the backbuffer, recreates them at the Viewport panel's `requested_width` / `requested_height` in `post_update` (a GPU idle), removes the ImGui textures in `pre_shutdown` and destroys the GPU ones in `shutdown`;
`EditorUiPlugin` owns the `Editor` (`editor/src/editor.hpp`: the panels, the selection, the scene dialogs and menus, reaching the other plugins through `engine->get_plugin<T>()`), creates ImGui and its SDL3 / Vulkan backends through `gpu/vulkan/vk_access.hpp` (the one Vulkan-specific piece of the editor), adds the Output panel as a log sink (`LOG::add_sink` of `OutputPanel::sink`, removed in `pre_shutdown`), clears the window plugin's `quit_on_close` so the close request goes through `Editor::request_quit`, feeds SDL events to ImGui in `events`, records the loaded scene as saved in `post_startup`, and adds a `ui` phase after `post_render` whose system draws the panels and renders ImGui into the frame's target, the backbuffer by then;
`EditorCameraPlugin`, `EditorGridPlugin` and `EditorHighlightPlugin` are described with the Viewport below.
The editor adds `EditorUiPlugin` before `ProjectPlugin`, so the project's messages already land in the Output panel;
the editor's own messages are `LOG_CATEGORY::EDITOR`, and its `main` sets the stderr sink to `LOG_WARNING` so the terminal keeps the problems while the panel shows everything.
The editor has one selection, `editor/src/selection.hpp`: a `Selection` (kind NONE / ENTITY / FILE, the entity, and for a file its project-relative path plus the entity the file is loaded as, 0 when none) owned by the Editor and handed to the Explorer, the Asset Browser and the Inspector, so clicking in one panel replaces the other's highlight;
`Editor::resolve_selection` runs before the Inspector draws and, once per picked `.material`, registers the file (`Engine::load_asset_file`) and loads it with `MATERIAL::load` so the selection carries the Material entity, and `Editor::apply_file_action` performs the Inspector's Save (`MATERIAL::save` to the file's path) or Reload (`MATERIAL::reload`).
A file whose entity carries `AssetDirty` shows "Modified, not saved" in the Inspector with the buttons reading Save* and Discard;
File > Save All (Ctrl+S, `Editor::save_all`, polled with `ImGui::Shortcut` so it works from any panel) writes every `Material` entity tagged `AssetDirty` through the pathless `MATERIAL::save`, then the scene when it needs saving, and reports each file in the Output panel.
The scene is a file: `ScenePlugin` opens the project's `scenes/demo.scene` at startup (falling back to `RENDER_DEMO::spawn`) and `Editor::mark_scene_saved` records it as the saved state in `post_startup`;
`Editor::open_scene` (`Engine::load_asset_file` + `Engine::load_scene`, clearing the selection) is how the editor switches scene afterwards;
File > New Scene / Open Scene... (Ctrl+O, the OS picker through a second `NativeFileDialog`, `scene_dialog`) / Save Scene / Save Scene As... (`NativeFileDialog::save_file`, SDL3 `SDL_ShowSaveFileDialog`, `.scene` appended when missing), a double-clicked `.scene` in the Asset Browser and Create > Scene (a `.scene` holding only a fresh `guid`) are the other ways in;
the Explorer's first line is the scene's project-relative path (`ExplorerPanel::scene_title`, `(unsaved scene)` for a new one) with a `*` while `Editor::scene_dirty` is set, which the panels raise through `ExplorerPanel::changed` (New Entity) and `InspectorPanel::changed` (a rename, an edited component, an added component) when the selected entity is scene content, and `Editor::scene_needs_save` backs the flag with a hash of `Engine::write_scene` against the one recorded at the last load or save (`scene_saved_hash`);
New, Open and Quit (the window close too) go through `request_*`, which keeps the action in `Editor::pending` and opens the Unsaved Scene modal (Save / Save As... / Discard / Cancel) when something would be lost, `perform_pending` running it once the save went through (a Save As waits for the dialog) or the changes were discarded (Quit ends in `Engine::quit`).
The Viewport is always the fly camera: `EditorCameraPlugin` sets `Renderer::camera` to it and the editor's `ScenePlugin` has `tag_render_camera` off, so a scene file's `RenderCamera` tag is kept for the standalone.
The Viewport also draws a ground grid (`editor/src/editor_grid.hpp`: `EditorGrid`, the shader `render/editor/grid.slang`, a y = 0 quad from the vertex index, `#pragma pass grid_editor ... blend depth_test no_depth_write no_cull`): a `RENDER_PASS_CUSTOM` graph pass named `alpha` whose callback `editor_grid` binds the pipeline from `PIPELINES::get` with no mesh layout and draws six vertices, color attachment the backbuffer loaded, depth attachment the forward pass's depth loaded;
`update` each frame (`EditorGridPlugin`'s `post_update` system) keeps the pass last in the graph order and the forward pass's depth store at STORE and follows its depth resource, since the demo toggles rewrite both, and the plugin's `pre_shutdown` system removes the pass and the callback;
Render > Grid toggles it (`set_enabled`), and it is the slot a transparent-object DRAW_SCENE pass tagged `alpha` would take later.
The Viewport outlines the selection (`editor/src/editor_highlight.hpp`: `EditorHighlight`, an `Outline` of the engine's `engine/render/outline.hpp` named `selection`, 8 pixels wide at most and with the occluded side on):
everything but the mask is the engine's, so a game's own outline is the same chain and the same `render/outline.slang` with `behind` left off, and what the editor adds is a mask callback that draws the selected entity through `render/editor/selection.slang` (`OUTLINE::draw_mask`),
which exists because a selected object keeps its own material and so cannot carry the `outline_mask` pass itself the way a game's objects do.
`EditorHighlightPlugin`'s `post_update` system hands it the selection off `EditorUiPlugin` (only scene content: `Scene::contains`) and the grid's pass to stay in front of, so the grid draws over the outline, and its `pre_shutdown` system removes the chain;
with nothing selected the whole chain is disabled, which recompiles the graph on the click that empties the selection rather than flooding the screen every frame;
add it after `EditorGridPlugin`, since both order themselves in `post_update` and the grid keeps itself last.
Render > Selection Outline toggles it.
Playtesting (`docs/playtesting_plan.md`): the Play button centered in the menu bar (then Pause / Resume, Step and Stop), the Play menu (Ctrl+P plays and stops, Ctrl+Shift+P pauses and resumes, F10 steps, a time scale slider) and the Stats panel's `Play:` line drive `PlayPlugin` through its `request_*` calls;
while a game runs every panel shows the play world, since `engine.get_singleton<World>()` resolves to the instance's, the Explorer's title says `(playing)` / `(paused)` and tints the entities the game created (`ExplorerPanel::runtime_from`, the play fence), the Inspector says that edits end with the game, and the scene file is left alone: New / Open / Save / Save As, Save All, Refresh Assets, Reload Shaders and the file Save / Reload buttons are off, the panels' changes do not raise the dirty flag and `scene_needs_save` returns the flag alone instead of hashing the play world;
`EditorCameraPlugin` moves the fly camera in the root world only and does not fly while playing (the Viewport shows the game's camera), and `EditorGridPlugin` / `EditorHighlightPlugin` edit the root renderer's graph only (`engine.root.get<Renderer>()`), so the grid and the outline are simply not in the play instance's frame.
A component's draw function never adds components itself, so when a pick needs an asset loaded it leaves an `InspectorRequest` in its `InspectorContext` (LOAD_MATERIAL: `MATERIAL::load` of the picked `.material` asset entity;
SET_MATERIAL_SHADER: `SHADER_LIBRARY::load` of the picked shader asset by its name, then `MATERIAL::set_shader` on the target entity),
which the panel keeps in `InspectorPanel::request` and `Editor::apply_inspector_request` performs after the draw.
Editor panels live in `editor/src/ui/` (`output_panel` (a `LogSinkFn` keeping every record with its level, category, file and line, drawn as `[category] file:line: text` with the level's color, a text filter and a Categories popup that hides categories from view without touching the log's own switches),
`explorer_panel` (the scene tree: `draw(open, world, scene, selection)` lists `scene_root` and, under each expanded node, its `CHILD_OF` children through `SCENE::children`, read fresh every frame, then after a separator the editor's own unparented `editor_camera` entity (`ExplorerPanel::editor_camera`, set by the UI plugin) so its Transform can be inspected;
rows show the `Name`, the filter keeps matching subtrees open, a click calls `selection.select_entity`, a selected entity that dies clears it;
right-clicking a scene row opens a context menu whose New Entity spawns a child of it through `SCENE::spawn` with a `Name` and an identity `Transform`, selects it and opens the parent node on the next frame (`ExplorerPanel::reveal`),
right-clicking the tree's empty space does the same under `scene_root`, and editor-only rows get no menu),
`inspector_panel` (`draw(open, world, project, selection)`: for an entity an editable Name header, then one collapsing section per archetype id whose component entity has an `Inspector`, drawn by its function with an `InspectorContext` (`ui/inspectors/inspector_context.hpp`: world, entity, id, and a 128-byte per-(entity, id) scratch zeroed on first use and dropped when the selection changes) and turned into `World::modified` when it reports a change;
ids without one are listed under "Other" by name, pairs as `(CHILD_OF, parent)`;
for a file its name, kind, folder and size, and when the file is loaded as an entity the Save / Reload buttons (reported through `file_action` for the Editor) followed by that entity's component sections the same way),
the draw functions in `ui/inspectors/` (`INSPECTORS::register_all` exposes `Transform` (position, Euler-degree rotation cached in the scratch so the fields do not jump while editing, scale),
`Camera` (field of view in degrees, near, far),
`MeshRenderer` (mesh combo over the mesh assets plus `none`, material combo) and `PrimitiveRenderer` (shape combo, material combo over the material assets plus `none`;
picking a `.material` nobody loaded yet points the field at its asset entity at once and files a LOAD_MATERIAL request),
and `Material` (`material_inspector.cpp`: the shader as a combo over the shader assets (a pick files a SET_MATERIAL_SHADER request, the field itself is never written there), every block member as a field by its reflected type (3- and 4-float vectors as HDR color edits, matrices one row per column, bools as checkboxes) written straight into the block, texture slots as a combo over the texture asset entities (`world.query<AssetUuid>().with<ECS::Pair<AssetType, AssetTexture>>()`, listed by `Name` sorted, plus `none`;
the GUID in the tooltip;
a GUID no entity carries is shown as such and kept;
every one of these combos is `ui/inspectors/asset_combo.hpp`: `ASSET_COMBO::collect(world, ASSET_TYPE::*)` lists one type's asset entities by `Name`, `draw` is the combo that keeps an unlisted current value selectable, and `material` / `mesh` / `shader` are the per-field combos the inspectors call),
sampler slots as their words parsed on Enter with the typed text held in the scratch) and `AssetUuid` (`asset_inspector.cpp`: type and GUID, read-only, under the "Asset" header);
`register_all` also marks `Transform`, `Camera`, `MeshRenderer` and `PrimitiveRenderer` `Addable`, the renderers with `INSPECTORS::default_mesh_renderer` (no mesh yet) / `default_primitive_renderer` (a cube), both using the lowest-id `Material` entity;
an entity's Inspector ends with an "Add Component" button whose menu lists every `Addable` component by its Inspector name, held ones disabled, and calls `INSPECTOR::add` after the menu closed),
`asset_browser_panel` for the open project's files (a click calls `selection.select_file` with the project-relative path and the row highlight mirrors the selection, dropping when another panel selects;
rename and new-folder reselect the result, delete clears it;
double-clicking a file sets `activated`;
right-click opens a context menu: Import on importable files sets `activated` like a double-click, on a `.lunaasset` Reimport and Save Original... act on the kept original (`IMPORT::find_source` probed when the menu opens, both disabled when none was kept;
Reimport reports `reimport_source` + `reimport_asset` for the Editor to queue, Save Original... asks for a path in a modal and writes the bytes with `IMPORT::save_source`),
Delete removes the entry after a confirmation modal, Rename... (or F2 on the selection) asks for a new name in a modal, New Folder... creates a folder in the current one after asking for a name in a modal;
right-clicking the empty space of the listing offers New Folder..., Create and Refresh;
the toolbar's Create dropdown (the same entries as the Create submenu of both context menus: Material, Scene, Shader > one entry per engine shader, Code > Luau / Cpp) writes a template file in the current folder through the name modal with the extension fixed (a `.material` with a fresh GUID on the `unlit` shader and `color = 1 1 1 1`,
a `.scene` with a fresh GUID and no entities,
a byte-for-byte copy of the picked engine shader (every `.slang` directly in the engine's `render/`, which the UI plugin hands the panel as `shader_template_dir`, listed by stem on each refresh, the empty `surface.slang` included, defaulting the name to `new_<stem>`),
a `.luau` or `.cpp` stub;
`AssetBrowserPanel::create_file`) and selects it, so a new `.material` lands in the Inspector at once;
all reporting through `LOG::` as `LOG_CATEGORY::EDITOR`),
`import_panel` (a floating window: queue of source files, per-kind `MeshImportOptions` / `TextureImportOptions` including a "Keep original" checkbox, destination folder + name, runs `OBJ::import` / `IMAGE::import`;
`open_reimport(source, asset)` queues the original kept in a `.lunaasset` instead, titled Reimport (`PANELS::REIMPORT`, same `###Import` id),
header showing the asset and its original, destination defaulting to the asset itself, which keeps its GUID when written in place and gets a fresh one anywhere else),
`format.hpp` (`UI::format_size`),
`dock_layout` for the default docking, `panels.hpp` for the window titles);
the Editor draws Viewport and Stats itself (the Viewport panel shows the viewport plugin's texture, asks it for its size and tells the camera plugin whether the image is hovered).
The Viewport is drawn from the editor's own camera (`editor/src/editor_camera.hpp`: the editor-only `EditorCamera` tag and `EditorCameraController`, which spawns the unparented `editor_camera` entity with `Transform` + `Camera` + `EditorCamera` + `RenderCamera`, so it never appears in the scene tree, and each frame in the `update` phase (`EditorCameraPlugin`, the wheel taken from the window plugin's events in `events`) reads SDL's input state: right mouse held over the Viewport image enters fly mode with SDL relative mouse mode, the mouse yaws / pitches (no roll, pitch clamped),
WASD / E / Q move, Shift multiplies the speed, the wheel scales it;
releasing the button ends it and warps the cursor back to where it was;
the window focus flag is deliberately not consulted, since it flapped under a Wayland pointer lock and re-locked every frame).
File > Import... opens the OS picker through `editor/src/file_dialog.hpp` (`NativeFileDialog`, SDL3 `SDL_ShowOpenFileDialog`: async callback stores paths under a mutex, `take()` drains them on the main thread each frame);
the picked files and double-clicked `.obj` / image files in the Asset Browser both land in the Import panel, with the browser's current folder as destination.
The open project is the runtime's `Project` (`engine/project.hpp`), opened and scanned by `ProjectPlugin`.
There is no open-project page yet: the editor's `main.cpp` adds `ProjectPlugin(EDITOR_TEST_PROJECT_DIR)` (`editor/testing_project/`, set in `editor/CMakeLists.txt`;
it holds sample `meshes/*.obj` and `textures/*.png` to import, and `materials/demo.material`), whose scan registers the assets and the shader files (the engine's `render/` then the whole project, the override and duplicate rules in `engine/runtime/CLAUDE.md`), so the Inspector can offer shaders not compiled yet and a project shader may sit in any folder;
a listed shader that fails to compile (an empty file, a Slang error) stays listed and reports the error when picked;
File > Refresh Assets runs `PROJECT::scan` again (registering a file twice only refreshes it) and refreshes the Asset Browser, which is how a shader or material file created after startup reaches the dropdowns.
Importers live in `editor/src/import/`: `importer.hpp` (`ImportSource`: the bytes to import as a path + offset + size + original name + the asset's GUID when they sit inside a `.lunaasset`, `ImportSource::file(path)` for a plain file;
`IMPORT::read_file` / `read_source`, `find_source(asset)` probes a `.lunaasset` for its kept original, `save_source` writes it out, `fnv1a` for `content_hash`, `random_guid`, `add_editor_chunks(writer, source, bytes, size, keep_source)` writes the NAME / IMPS placeholders and the SRC chunk or its placeholder, `write_asset`),
`obj_importer.hpp` (`OBJ::parse` text -> `ObjMesh`, one interleaved 32-byte stream of position/normal/texcoord, fan-triangulated, one submesh per `usemtl`, smooth normals generated when absent, v flipped;
`OBJ::import` `ImportSource` -> `.lunaasset` through `MeshAssetWriter`) and `image_importer.hpp` (`IMAGE::decode` via vendored stb_image into a `DecodedImage` in R8/RG8/RGBA8 or the 16-bit UNORM variants, RGB promoted to RGBA;
`IMAGE::import` `ImportSource` -> `.lunaasset` through `TextureAssetWriter`).
Decoders stay in the editor because core has no external dependencies;
engine_tests links only core, so importer behaviour is not covered by `engine_tests`.
